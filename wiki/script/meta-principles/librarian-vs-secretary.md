# 사서 vs 비서 — ClipFlow LLM 위키의 차별점

## 비유

| 사서형 (NotebookLM 등) | 비서형 (LLM 위키) |
|---|---|
| 도서관 앉아 있음 | 항상 옆에 있음 |
| 물어보면 → 책 찾아줌 | 자료 주면 → 알아서 정리·연결 |
| 사용자가 능동 | AI가 능동 |
| 인덱스 기반 검색 | 의미 기반 합성 |

---

## 기능 비교

| 기능 | 사서형 | 비서형 (ClipFlow 지향) |
|---|---|---|
| 자료 추가 | 사용자가 업로드 | URL·텍스트 던지면 자동 분류·요약·연결 |
| 질문 답변 | 자료 안 검색 → 답 | 위키 참조 → 합성된 답 |
| 자료 간 관계 | 독립 (인덱스만) | 자동 연결 (entities·concepts·claims) |
| 누적 효과 | 자료 양에 비례 | **복리 구조** (위키 늘수록 결과 품질 점프) |
| 사용자 부담 | 정리 부담 큼 | 결정·검토만 |

---

## ClipFlow 영상 생성에서 적용

### 기존 (사서형 흐름)
```
사용자 → "유튜브 대본 써줘" → AI 검색 → 답 → 끝 → 다음에 같은 질문 또
```

### ClipFlow (비서형 흐름)
```
사용자 → 자료 던짐 (URL·문서·과거 영상)
       ↓
LLM 위키 자동 분류·정리·기존 지식과 연결
       ↓
사용자 → "이번 주제로 영상" 한 마디
       ↓
AI가 누적 위키 참조 → 사용자 voice + 카테고리 톤 + 5단계 검수 → 영상
       ↓
결과·피드백도 다시 위키에 누적
       ↓
다음 영상 = 더 똑똑해진 상태에서 시작
```

→ **자료 던지기·결정만** 사용자가 하고, **정리·연결·합성**은 AI가 자동.

## ClipFlow 구현 매핑

| 비서형 기능 | ClipFlow 구현 위치 |
|---|---|
| 자료 자동 분류 | `src/app/api/wiki/sources/ingest/route.ts` |
| 위키 자동 연결 | `wiki/script/_shared/` 공유 구조 |
| 위키 합성 | `src/app/api/wiki/synthesis/route.ts` |
| 누적 학습 | `feedback/{category}/YYYY-MM-DD.md` |
| 사용자 voice | `wiki/script/{category}/identity.md` + `tone.md` |

## 마케팅 메시지 (PRODUCT_SENSE.md 후보)

> **"ClipFlow는 검색해주는 도구가 아닙니다. 알아서 정리하고 영상을 만들어주는 비서입니다."**

vs 경쟁사 (Vrew·CapCut·Pictory):
- 그들 = 사용자가 입력 → 결과 (사서형)
- ClipFlow = 자료 누적 → 자동 영상 (비서형)

→ 사용자 한 명이 ClipFlow 오래 쓸수록 **영상 품질이 자동으로 올라감.**
